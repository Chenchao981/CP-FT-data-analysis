# TMS 清洗能力模块化第一阶段完成报告

日期：2026-09-04

## 结论

TMS 已建立“测试阶段 → 厂家 → 清洗能力 → 原始格式方法 → 正式 Cleaner”的模块化基础。CP/FT 外部工具继续负责具体解析、单位、规格、Bin 和统计规则；TMS 只登记能力、校验正式包 SHA、校验合同并调度执行。

本次已将立昂微和电基拆到格式方法级。根据业务确认，CP/FT 工具发布目录中的包均为已经过生产实践的正式版，版本历史由 Git 管理；TMS 不增加候选版、Canary 或多通道发布流程。新版立昂微清洗包已登记为正式 Release 59，并直接成为 TMS 当前正式清洗方法。

## 做了什么

1. 新增统一 Cleaner Capability Registry：
   - 立昂微 CP 标准清洗：V1 动态参数 Excel、V2 已批准 OLE XLS。
   - 电基 FT 正式清洗：PowerTECH 文本伪 XLS、PowerTECH 原生 XLSX。
   - 电基 FT 个人目录 PAT：在正式清洗两种格式基础上，增加 STS8203 CSV、TF CSV。
2. 新增 `/api/v1/contracts/cleaner-capabilities`，供管理界面和后续发布流程读取厂家、用途及格式方法关系。
3. Runner 在执行前校验厂家、阶段、Cleaner、输入合同、输出合同及格式方法清单；已登记能力发生错配时拒绝执行。
4. TMS 直接登记 CP/FT 工具发布目录中的正式包：
   - 版本开发和回退记录由外部工具 Git 仓库负责。
   - TMS 记录正式包 SHA-256、能力合同和执行入口，用于运行校验和数据追溯。
   - 相同版本号与不同 SHA 冲突时拒绝登记，防止误用错误包。
5. 新版立昂微正式包已登记为 Release 59：
   - 状态：`RELEASED`
   - 版本：`sha256-e970e3e3e10c`
   - SHA-256：`e970e3e3e10cfc3a7561cdb4653acd20092677bf329f635c004e2770a9fcdf34`

## 确定的边界

- 厂家不是一个巨大解析函数；厂家能力内部可以包含多个独立格式方法。
- 正式清洗与个人工具可以共享同一底层方法，但允许的方法集合和输出合同分别控制。
- 更新 CP/FT 正式工具后，TMS 校验 SHA 并直接登记为当前正式方法；Git 负责源码和发布历史。
- 已经入库的历史 Dataset 不因工具更新自动重算。
- 未知格式、合同错配、SHA 不一致、坐标重复和规格冲突均失败关闭。

## 尚未完成

- 当前阶段的能力目录为代码级 Registry；尚未增加管理界面的清洗能力查看页面。
- 除立昂微、电基外，其余厂家仍按原有 Adapter 工作，后续应逐厂家迁移到格式方法级 Registry。
