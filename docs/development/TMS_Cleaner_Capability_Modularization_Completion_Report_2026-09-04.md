# TMS 清洗能力模块化第一阶段完成报告

日期：2026-09-04

## 结论

TMS 已建立“测试阶段 → 厂家 → 清洗能力 → 原始格式方法 → Cleaner Release”的模块化基础。CP/FT 外部工具继续负责具体解析、单位、规格、Bin 和统计规则；TMS 只登记能力、绑定不可变发布包、校验合同并调度执行。

本次已将立昂微和电基拆到格式方法级，并把新版立昂微清洗包登记为候选 Release 59。候选版本保持 `DRAFT`，现行稳定 Release 46 未切换，正式任务和个人工具不会静默使用候选包。

## 做了什么

1. 新增统一 Cleaner Capability Registry：
   - 立昂微 CP 标准清洗：V1 动态参数 Excel、V2 已批准 OLE XLS。
   - 电基 FT 正式清洗：PowerTECH 文本伪 XLS、PowerTECH 原生 XLSX。
   - 电基 FT 个人目录 PAT：在正式清洗两种格式基础上，增加 STS8203 CSV、TF CSV。
2. 新增 `/api/v1/contracts/cleaner-capabilities`，供管理界面和后续发布流程读取厂家、用途及格式方法关系。
3. Runner 在执行前校验厂家、阶段、Cleaner、输入合同、输出合同及格式方法清单；已登记能力发生错配时拒绝执行。
4. Cleaner 登记支持 `DRAFT` 和 `RELEASED`：
   - `DRAFT` 不会被正式入库或个人工具选择。
   - 候选包按 SHA-256 保存不可变快照。
   - 发布提升必须同时提供 Release ID、预期 SHA-256 和显式 `--promote`。
   - 不带 `--promote` 时只做只读校验。
5. 新版立昂微包已登记为 Release 59：
   - 状态：`DRAFT`
   - 版本：`sha256-e970e3e3e10c`
   - SHA-256：`e970e3e3e10cfc3a7561cdb4653acd20092677bf329f635c004e2770a9fcdf34`

## 确定的边界

- 厂家不是一个巨大解析函数；厂家能力内部可以包含多个独立格式方法。
- 正式清洗与个人工具可以共享同一底层方法，但允许的方法集合和输出合同分别控制。
- 更新 CP/FT 工具后，TMS 新建不可变候选 Release，不覆盖旧包，不重算历史 Dataset。
- 未知格式、合同错配、SHA 不一致、坐标重复和规格冲突均失败关闭。

## 尚未完成

- 当前阶段的能力目录为代码级 Registry；尚未增加管理界面的可视化发布操作。
- 数据库目前使用 `DRAFT`/`RELEASED`，尚未扩展完整的 `CANDIDATE`/`CANARY`/`STABLE` 通道模型。
- 除立昂微、电基外，其余厂家仍按原有 Adapter 工作，后续应逐厂家迁移到格式方法级 Registry。
- Release 59 尚未提升为正式版本；需完成指定范围的 Canary 任务及业务确认后再显式提升。

## 下一步

1. 先在指定立昂微批次上用 Release 59 做 Canary，不影响现行 Release 46。
2. 对通过的 Canary 保存源文件清单、SHA、行数、Bin、规格指纹和参数差异报告。
3. 业务确认后显式提升 Release 59；若失败，继续使用 Release 46，无需回滚数据。
4. 按相同模型逐步迁移日月新、华虹、国宇、捷泰等 CP/FT 厂家。
