# NCE PYMS 个人快速分析结果历史改造完成报告

**日期：** 2026-09-04

**范围：** CP/FT 个人快速 PAT、服务器结果历史、真实源数据验证

**结论：** 核心链路已完成并通过 CP 与 FT 真实数据验证。

## 一、本次落定的业务边界

1. 正式 CP 和 FT 仍走正式制造数据链路：上传或受控数据源 → 格式识别 → Cleaner 清洗 → 正式数据 → 按需统计/图表。
2. 个人工具用于一次性快速分析：直接读取个人电脑或已共享路径的文件，不将原始文件写入正式数据库。
3. 个人分析仍复用已发布的 CP/FT Cleaner 和 PAT 算法，不另造一套口径。
4. 任务成功后，服务器只保留 PAT 报告、统计摘要和来源 Manifest；原始文件、标准化清洗文件和计算中间文件不保留。
5. 成功结果作为用户的历史分析结果长期保留，不再被快速工作区的到期清理任务删除。失败或取消任务的临时文件仍按原策略清理。

## 二、已完成改动

- 成功分析不再因会话截止时间变成“已过期”。
- 成功结果在 SQL Server 中登记为非临时 Artifact，`temporary_flag=0`、`expires_at_utc=NULL`。
- 快速工作区清理仅选择失败或取消的任务，不选择已成功的历史结果。
- 个人 PAT 不再强制填写额外输出目录；服务器历史是默认保存位置，本地副本仅作可选导出。
- 个人工具页增加“历史分析结果”语义，明确标识“服务器历史”。
- 个人工具页同时提供“同机/共享路径”和“个人电脑 Agent”两种入口，两者都不把原始文件写入正式数据资产。
- 增加可重复使用的真实数据验证脚本，支持已注册的 4 个 CP 和 5 个 FT 快速 PAT 工具合同。

## 六、已知边界与下一步

1. “同机/共享路径”只能读取 TMS 运行电脑可见的本地盘、映射盘和 UNC 共享。本次真实验证中 TMS 与源数据在同一台 Windows 电脑，因此可直接读取 `F:` 盘。
2. TMS 部署在远程服务器时，必须使用“个人电脑 Agent”才能读取用户本机目录且不上传原始数据。当前 Agent 已验收杰群 FT PAT；其他 CP/FT 工厂的 Agent 本机执行合同仍需逐一接入和 Golden 验证。
3. 当前“历史分析结果”已支持列表、明细图表和下载；尚未增加用户主动删除单个历史结果的功能。
4. 完整产品范围内的 Cleaner、统计和图表能力仍按工厂/数据类型分批接入；本次不将界面中标注“网页待接入”的清洗、图表或 SBL/SYL 冒充为已完成。
