# NCE PYMS 第一阶段核心任务审计与收口报告

- 日期：2026-09-04
- 当前基线：`NCE_PYMS_Functional_Roadmap_v1.0_2026-09-03.md`
- 审计范围：正式 CP/FT、个人分析工具、Cleaner 模块化、分析规则、图表结果、数据源与本地运行

## 一、结论

第一阶段的“人工可用主链路”已经形成：

1. 正式 CP/FT 可以上传源文件或提交受控服务器目录，后台调用已发布 Cleaner，形成正式 Dataset，并进入产品、批次和图表分析。
2. 个人分析工具可以直接读取同机、共享路径或个人电脑 Agent 可见的数据，执行一次性 PAT，只在服务器保存结果和历史，不保留原始文件与清洗中间文件。
3. 本地 API、Worker、网页和 SQL Server 版本保护可以一键启动并同时确认就绪。

第一阶段尚不能宣告“全部完成”。当前剩余的核心缺口是：

- Cleaner 格式方法级 Registry 只完成了立昂微和电基，其余已接入厂家仍通过旧 Adapter 运行；
- 分析规则自动匹配的程序链路已完成，但当前开发库没有任何已批准并启用的分析规则，高级统计/质量图表会按设计保持不可用；
- 数据源中心已具备已配置目录查看、目录清单确认和人工提交入口，尚未形成定时扫描、自动入队、重试和监控闭环；
- 个人工具当前稳定闭环是 PAT，页面上清洗、散点图、SBL/SYL 等标为“待接入”的按钮仍未实现；
- 当前结论是本地开发环境验收，不是目标服务器、真实登录权限、UAT 或生产上线结论。

因此，下一阶段不继续横向增加菜单和图表，而是按“规则配置门禁 → 重点厂家模块化 → 正式数据源自动采集”顺序收口。

## 三、Cleaner 模块化现状

### 已完成

- 立昂微 CP：动态参数 Excel、已批准 OLE XLS 两种格式方法；正式 Release 59 已验证。
- 电基 FT：PowerTECH 文本伪 XLS、原生 XLSX；个人 PAT 额外包含 STS8203 CSV、TF CSV。
- Runner 会核对测试阶段、厂家、Cleaner、输入合同、输出合同、格式方法和正式包 SHA，错配时失败关闭。
- 历史 Dataset 不因 Cleaner 更新自动重算。

### 未完成

- 正式链路的华虹、积塔、日月新、日月光仍为旧 Adapter，没有拆成格式方法级能力。
- 个人快速 PAT 的华虹、积塔、国宇、日月新、日月光、杰群、集佳等尚未全部进入统一 Cleaner Capability Registry。
- 管理页面还不能直接查看“厂家 → 用途 → 格式方法 → 正式包版本 → SHA”的能力目录。

### 建议迁移顺序

1. 日月新 FT 正式清洗：现有正式 Dataset 数量多，先保护最常用链路。
2. 华虹 CP 正式清洗：现有 CP 数据与 Yield 证据完整，适合作为第二个 Golden。
3. 积塔 CP、日月光 FT：完成其余当前正式入口。
4. 杰群、集佳、国宇等个人工具：按个人 PAT 实际使用频率迁移，不反向扩大正式入库范围。

## 四、本轮核心开发

本轮聚焦 P0-3，没有继续扩展新菜单或新图表。

已完成：

1. 服务端分析 Context 新增“当前上下文可用规则版本”，仅返回同时满足以下条件的规则：
   - 已发布；
   - 已启用且处于有效期；
   - 业务、技术、质量三方均批准；
   - 测试阶段、厂家、产品和参数范围匹配；
   - 对本次选择的全部 Dataset 均适用。
2. CP/FT 图表选择页根据服务端返回的适用规则决定高级方法是否可用，普通用户不再填写规则编号或版本。
3. 修复参数范围规则的闭环：用户选择参数后，页面会携带已选参数重新请求 Context；否则参数级规则会一直被误判为不可用。
4. 重新匹配期间保留已加载的参数列表，避免查询刷新把用户刚选择的参数清空。
5. 增加参数级规则重新匹配的前端回归测试。

## 六、确定的边界

- 第一阶段可用不等于所有高级质量规则已经批准，也不等于 FTP/NAS 已实现无人值守采集。
- 没有 PASS/FAIL、Bin 或正式规格时，Yield、OOS、Cpk/Ppk 等保持未知或不适用，不能补 0。
- 个人分析结果不得进入正式良率、管理驾驶舱和异常预警。
- 当前旧 Adapter 可以继续提供已经验收的能力；迁移 Registry 时不得重写成熟厂家解析器。
- 国宇目前属于个人定制工具范围，不能因为历史正式数据存在就自动重新开放正式通用上传。

## 七、下一步执行顺序

1. **完成第一阶段规则配置门禁**：盘点 CP/FT 现有正式算法和批准口径，形成规则登记清单；没有业务批准的规则继续不可用。
2. **迁移日月新 FT Cleaner 能力**：拆分 DC 等已验收格式方法，登记正式包 SHA 和合同，用真实源数据做 Golden 对账。
3. **迁移华虹 CP Cleaner 能力**：保持现有正式上传和 Canonical 结果不变，只替换能力登记与调度约束。
4. **补 FTP/NAS 自动采集最小闭环**：定时扫描、指纹去重、自动入队、失败重试和任务状态，不先建设复杂调度平台。
5. **做第一阶段业务验收**：至少使用一个 CP 产品和一个 FT 产品，从上传/目录提交走到清洗结果、基础图表和历史查询；另用一个个人 PAT 样本确认只留结果。

只有以上五项完成后，再把产品驾驶舱、异常闭环和综合报告作为下一阶段主任务。
