# NCE PYMS 个人工具清洗、散点与 SBL/SYL 完成报告

- 日期：2026-09-04
- 范围：个人工具一次性清洗、CP 图表、FT 散点、PAT、SBL/SYL、结果历史与下载
- 本地环境：`TMS_G0_DEV / sql2014_0026`

## 一、做了什么

1. 个人工具新增三类后台任务：数据清洗、图表/散点分析、SBL/SYL；原 PAT 任务保持兼容。
2. TMS 继续调用已发布 CP `app.pyz` 和 FT `ft_data_cleaner.pyz`，运行前校验 Release、输入合同和包 SHA，不复制重写厂家解析、规格、Bin 或统计逻辑。
3. CP 清洗生成标准 CSV 结果包；CP 图表调用现有 Yield、Boxplot、Summary 组件生成离线 HTML 结果包。
4. FT 清洗按厂家调用现有 Cleaner；日月新、杰群、电基散点调用现有散点 Manifest 和绘图逻辑；日月新、杰群、电基 SBL/SYL 调用现有良率报告逻辑。
5. 清洗和图表结果以 ZIP 保存，SBL/SYL 以 XLSX 保存。结果、摘要和源清单进入服务器历史，原始文件和清洗中间目录不保留、不进入正式数据表。
6. 历史列表增加功能类型和通用结果下载；只有 PAT 结果展示参数明细。
7. 数据库任务类型约束升级到 `sql2014_0026`；会话详情和结果下载遇到 SQL Server 1205 死锁时自动短暂重试。
8. 个人工具页面移除临时 FTP 页签。FTP/NAS 定时自动采集和 SAP-B1 关联按用户决定暂缓。
9. 修正国宇单文件个人分析的目录身份传递：TMS 从原路径保留产品和批次目录语义，再调用现有国宇 Cleaner，避免把临时目录名 `SOURCE` 当成批次号。

## 五、确定的与尚未确定的

确定的：

- 个人任务读取用户指定路径，原始数据不进入正式数据库；只保留结果、摘要和源清单。
- 个人结果不进入正式良率、管理驾驶舱、异常预警或正式 Dataset Current。
- SBL/SYL 是单个良率 Excel 输入，不能用 PAT 的原始目录规则代替。
- 积塔、立昂微、国宇已分别用真实样本完成 TMS API、SQL 队列、Worker、已发布 Cleaner、结果历史和下载的整链路验证。
- 本轮本地 API、Worker、前端与数据库版本一致并可运行。

尚未确定的：

- 本轮不是目标服务器、真实登录权限或生产上线验收。
- 本轮已完成积塔、立昂微、国宇的真实样本全链路验证，但严格业务 Golden 仍需业务负责人冻结样本 SHA 以及预期行数、Bin、规格和良率摘要，才能作为后续版本的独立数值回归基线。
- 异常发现、确认、分派和关闭的业务闭环尚未完成，但不影响个人工具结果产出。
