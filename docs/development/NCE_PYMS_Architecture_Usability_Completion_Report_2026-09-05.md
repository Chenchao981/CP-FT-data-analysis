# NCE PYMS 架构与可用性优化完成报告

日期：2026-09-05。范围：用户授权的六项优化，沿用 9 月 3 日路线图及 9 月 4 日正式包/延期事项决定。本报告是本地开发验收，不是目标服务器或生产上线证明。

## 做了什么

| 方向 | 本次落实 | 边界 |
|---|---|---|
| CP/FT 架构 | 独立领域数据合同；存储适配器继续兼容原导入接口；CP 按 Lot/Wafer/XY 拒绝不同 Seq 的重复芯粒 | 物理事实表仍共享，分表迁移按扩展指南分阶段执行 |
| 结果解释 | 参数能力与分布拟合不可用原因转为中文；共用数据来源、计算方法、纳入/排除/缺失数量组件 | 未提供的数量显示未知；规格和业务规则不猜测 |
| 厂家扩展 | 六家正式能力统一登记；API 与清洗执行共用合同来源；运行一致性页展示能力及数据库登记的精确版本/SHA | 登记不等于实际包可执行，仍由执行时 SHA、合同和样本校验负责 |
| 员工电脑 | 个人电脑入口、连接故障说明；可迁移 ZIP 构建器；配置校验与运行依赖诊断分别提供 | 当前员工电脑执行仅接入杰群统一 CSV PAT；需已安装 Python 环境 |
| 正式/个人一致性 | 共用 PAT 结果解释；缺失异常数不再显示 0；现行正式统计核心与官方源码一致性验证 | 保留历史算法合同，未重算历史 Dataset |
| 回归及交接 | 前端测试改为文件串行避免资源竞争；真实样本性能、SQL 查询及本地执行链验证；更新导航和旧交接 | 未做 520 大目录实测，本次不是大规模容量上限证明 |

架构及扩展流程见 [CP/FT 阶段合同与扩展指南](../architecture/NCE_PYMS_Stage_Contracts_and_Extension_Guide_2026-09-05.md)。本轮不扩展 FTP 定时采集、SAP、工单或 AI，不增加 Canary 审批链。

## 确定的：验证证据

- 后端和本地程序全量回归：1,198 passed、4 skipped，54.10 秒；日志 `artifacts/runtime/optimization-backend-complete.log`。
- 前端完整回归：59 个文件、288 个测试通过，798.56 秒。串行提升稳定性，但执行时间较长。最后的正式 PAT 页面改动另做 6 项定向检查通过。
- 前端生产构建通过，24.68 秒；仍有大于 500 kB 的分块提示，未宣称首屏性能优化完成。
- 发布兼容修复后，发布包/本地程序定向 26 项通过；新增配置与执行环境区分测试 4 项通过。
- 正式 PAT 与官方 `compute_pat_stats`：4 组边界向量及 23 参数个人结果对账通过。官方源码文件增加其他函数导致 SHA 变化，只接受已知新 SHA + Git 版本，验证冻结源码及函数 AST 相同，再做数值对账；未知版本仍拒绝。未放宽正式算法清单的 SHA。
- SQL 参数与功能查询复核通过；正式 CP/FT 数据读取快照稳定。CP 7,356 个数值，冷查 600 ms、热查 567–586 ms；FT 86,026 个数值，冷查 1,762 ms、热查 1,600–1,723 ms。此为现有开发库样本。
- 杰群个人电脑服务链实测：49,539 行/23 参数，计算 2.132 秒，总耗时 3.016 秒；源文件上传字节 0，结果确认后本地工作目录已删除。测试工具未传服务器地址，因此此条不证明登录后的结果登记链。
- 员工电脑测试 ZIP 解压到独立目录后，严格运行环境诊断通过（`optimization-local-bundle-r2.json`）；交付测试包为 `NCE_PYMS_Local_Analysis_2026-09-05_r2.zip`。
- 新能力状态 API 在当前开发库返回六家正式登记版本；仅返回合同、版本、SHA，不暴露服务器包路径或执行配置。
- 测试环境重启后 API、Worker、前端就绪，保留原有认证，数据库 `TMS_G0_DEV / sql2014_0026`。

## 不确定的与下一步

1. 浏览器当前停在登录页；未取得已登录测试会话，因此本轮未完成登录后页面端到端复验。已有组件测试和接口/真实样本检查不能替代这项验收。
2. 第二台员工电脑与目标服务器尚未实测。包需要配置准确网页 Origin 和本机 Python 路径；跨机器 HTTPS/浏览器本地连接限制需现场验证。测试包使用 localhost，不可直接当作公司统一安装包下发。
3. 物理 CP/FT 分表涉及历史身份与数据量对账，尚未迁移。先按扩展指南建立新表写入/查询适配和逐 Dataset 核验，再切换，不改变已存历史事实。
4. 前端串行回归仍需约 13 分钟，且 jsdom 有伪元素样式提示。功能检查通过后可单独优化测试等待方式与页面分块，不能靠无限增大超时掩盖问题。
5. 工具能力状态表只证明数据库登记存在；各厂家新增格式仍要严格真实样本和 Golden 验收。未批准格式/规格继续关闭对应能力。

构建员工电脑测试包：在项目根目录执行 `scripts/release/build_local_analysis_bundle.py --package <官方FT包> --output <新ZIP路径> --origin <实际网页Origin>`。解压后 `start.cmd` 会执行 `--validate-only --check-runtime`，通过才启动。单独 `--validate-only` 用于发布配置检查，允许未启用工具并明确显示状态，不能作为电脑可运行证明。

旧 `.remember/remember.md` 已原样保存到本地归档并更新现状；不会把旧的四入口、Canonical 尚未实现等状态带入下一轮。
