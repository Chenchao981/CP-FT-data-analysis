# TMS 正式版前端信息层级优化完成报告

- 日期：2026-09-02
- 优化基线：`2ac3aef feat: extend quick PAT to all verified FT vendors`
- 技术栈：React + TypeScript + Vite + Ant Design + ECharts（保持不变）
- 范围：现有正式版前端的信息层级、操作效率和视觉一致性

## 1. 本次目标

本次没有重做系统，也没有改变数据权限、接口合同或 CP/FT 业务逻辑。优化遵循以下原则：

1. Data First：正式数据、状态和异常优先于装饰性内容。
2. Action First：路径输入、筛选、上传和分析动作进入首屏。
3. Table First：数据页优先展示筛选与表格，不用大卡片挤占纵向空间。
4. Common First：高频筛选直接展示，低频筛选折叠到“更多筛选”。
5. Semantic Color：颜色只用于状态、风险和主要动作，不用渐变和装饰动画表达业务。
6. Preserve Contracts：继续使用服务端权限、分页、URL Context 和 Canonical 数据合同，前端不重新计算业务口径。

## 2. 已完成优化

### 2.1 共用指标条

- 新增轻量 `MetricStrip` 组件，用一条紧凑状态带替代多个大号 KPI 卡片。
- 支持默认、主状态、成功、警告和失败语义色。
- 为屏幕阅读器保留 `list/listitem` 语义，并提供移动端两列布局。

### 2.2 个人驾驶舱

- 移除深色营销式 Hero、装饰 Wafer、旋转动画和大面积渐变。
- 首屏改为用户上下文、正式数据指标、趋势和需要关注的异常。
- 保留个人/数据域切换、正式数据、个人快速分析和常用入口。
- 图表改为浅色中性背景；PASS/FAIL/UNKNOWN 原有口径不变。

### 2.3 快速分析

- 将“本机 / NAS 路径”操作区放在任务统计之前。
- 路径说明压缩为一行，强调后端可直接访问本地盘、映射盘和 UNC 路径，无需上传源文件。
- 排队、计算、完成和失败改为紧凑指标条。
- 保留直接路径、已配置服务器和临时 FTP 三种现有入口，以及 CP/FT 已发布工具调用方式。

### 2.4 CP/FT 数据页

- 上传记录、处理状态和失败数量改为紧凑指标条。
- 晶圆厂/封测厂、产品、Lot、结果状态作为四个高频筛选直接展示。
- 上传状态和时间范围进入可展开的“更多筛选”。存在高级 URL 条件时自动展开，清空筛选时同步关闭。
- 表格更早进入首屏；服务端权限、分页和筛选参数保持不变。

### 2.5 数据分析页

- Dataset、Lot、Wafer、Parameter 作为高频 Context 常驻。
- Bin、Overall Result、Source、Tester、Program、Test Condition 进入“更多筛选”。
- 已启用高级条件时显示条件类别数量，并自动展开，避免隐藏生效条件。
- 保留 `ANALYTICS_CONTEXT_V1`、完整多选参数和 URL 状态，不使用首项替代多选。

### 2.6 运行一致性

- 发布链、Schema、API、Worker 和队列状态改为两条紧凑指标带。
- 最近失败任务提前到首屏，便于定位实际问题。
- 运行身份和状态分布移入可展开详情，Worker 表格和运维操作保留。

## 3. 明确保留的正式版合同

- 未修改后端 API、数据库 Schema、权限判定和数据可见范围。
- 未修改个人数据、数据域数据和正式数据的边界。
- 未修改 Quick Workspace 与正式 Canonical 数据的隔离。
- 未修改 CP/FT 解析、PAT、Yield、Bin、统计或规则版本口径。
- 未新增前端自动推断、自动识别或静默补默认值。

## 5. 当前限制与后续建议

1. 登录页仍保留品牌化渐变设计。它是短暂停留的身份入口，不是高频生产操作页，本轮不重做。
2. Analytics 各专业子页仍包含较多业务卡片。后续应根据实际使用频率逐页优化，不应为追求统一外观而一次性重构。
3. 当前生产包仍有大 Chunk 警告，属于加载性能优化项；本轮未改变现有代码分包策略。
4. 全量 Vitest 并发运行存在明显资源竞争和超时，需要单独治理测试性能，不能将其混入业务界面优化。

## 6. 结论

本次优化是在当前正式发布版本上做渐进式改进。现有技术栈、权限和数据合同全部保留，核心生产页面已经从“展示型界面”调整为“数据、动作和异常优先”的工作界面，可继续作为后续正式版本迭代基线。
