# TMS CP/FT 清洗结果名称列整理完成报告

- 日期：2026-09-03
- 范围：CP、FT 共用的“清洗结果”表格
- 变更性质：前端展示优化，不修改数据合同

## 1. 问题核对

原表格同时展示：

- `名称`：绑定后端 `data_name`。
- `产品名称`：绑定后端 `product_name`。
- `批号`：绑定后端 `lot_id`。

经代码核对，`data_name` 当前主要由 Lot 集合生成，无法取得 Lot 时才回退到清洗文件名。因此它不是稳定的产品业务名称，实际页面中经常与“批号”重复，且“名称”这一表头不能说明它的业务含义。

## 2. 已完成变更

- CP 和 FT 的“清洗结果”表都移除“名称”展示列。
- 保留“产品名称”，并将它作为左侧固定的首个业务字段。
- 保留“批号”，继续明确展示 Lot。
- 表格横向滚动宽度由 1900 调整为 1720，与减少后的列宽一致。
- 后端 `data_name`、API 返回模型和数据库字段均未删除，保证现有接口、历史数据及其他调用方兼容。

## 3. 验证结果

- 前端正式生产构建：通过。
- 新增的列去重定向测试：通过，确认“产品名称”存在、“名称”表头不存在。
- 浏览器实测 `/cp`：产品名称存在，名称不存在，批号存在。
- 浏览器实测 `/ft`：产品名称存在，名称不存在，批号存在。
- `StageDataWorkbench` 文件全量测试本次运行 17/18 通过；剩余一项是未修改的“受控服务器目录提交失败后刷新 Manifest”用例在 30 秒处超时。该用例单独复跑仍为超时，与清洗结果列展示没有执行路径关联。

## 4. 结论

页面现在只保留业务含义明确的“产品名称”和“批号”，消除了 `data_name` 与 Lot 重复造成的视觉和理解成本，同时没有破坏底层数据兼容性。
