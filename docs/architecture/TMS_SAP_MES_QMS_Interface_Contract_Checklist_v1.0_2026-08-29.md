# TMS 与 SAP-B1 / MES / QMS 接口合同清单 v1.0

- 日期：2026-08-29
- 状态：接口立项与联调前置清单
- 当前事实：TMS 尚未与 SAP-B1、MES、QMS 建立生产自动接口；本文件不代表接口已经上线
- 适用范围：新洁能 CP/FT 正式数据、产品与 Lot 追溯、质量分析及后续经营分析

## 1. 目的

本清单用于在接口开发前冻结数据所有权、业务键、时序、幂等、权限、对账和失败处理。任何系统若不能提供经业务 Owner 批准的字段合同和 Golden 样例，TMS 只能把其标识保存为来源观察值，不能自动升级为企业主数据，也不能用推断值覆盖正式事实。

## 2. 系统职责边界

| 对象 | 建议权威系统 | TMS 的职责 | 当前状态 |
|---|---|---|---|
| SAP 物料编码、物料组、产品平台、财务属性 | SAP-B1 | 保存经审批 crosswalk；不自行创建或改写 SAP 主数据 | 仅有待审批 crosswalk |
| 采购/委外供应商、业务伙伴编码 | SAP-B1 | 将厂家来源代码映射为已批准供应商编码 | 未接入 |
| 生产订单、委外单、批次收发、库存数量 | SAP-B1 / MES，待业务确认 | 只引用明确单据键；不从 CP/FT 文件反推会计库存 | 未接入 |
| Wafer Lot、Assembly Lot、Test Lot、工艺路线与站点过账 | MES，待业务确认 | 保存稳定标识和事件版本，用于 CP→封装→FT 追溯 | 未接入 |
| CP/FT 原始结果、Cleaner Release、Canonical Measurement | TMS | 保留来源、SHA、处理链和 Dataset Version | 已建立仓库能力 |
| 规格批准、偏差放行、8D/CAPA、质量判定 | QMS，待业务确认 | 引用批准记录；不把分析建议自动变成放行结论 | 未接入 |
| 成本、标准价、实际价、毛利 | SAP-B1 / 财务数据仓库，待财务确认 | 只在财务口径冻结后关联分析，不在 TMS 重算会计凭证 | 未接入 |

## 3. 必须先批准的 Crosswalk

### 3.1 产品与物料

TMS 当前的 `raw_product_code` 是 Cleaner 从来源文件观察到的产品文本。它与 SAP-B1 `ItemCode` 不是天然等价关系。审批至少需要：

- 来源厂家、CP/FT 阶段、来源产品代码；
- TMS `product_id` 与来源观察时间范围；
- SAP-B1 `ItemCode`、物料名称、有效起止时间；
- 产品版本、封装、晶圆版本等可能造成一对多的区分字段；
- SAP 主数据 Owner、审批人、审批时间、依据和撤销原因。

同一来源键不能在有效期内映射到多个 SAP 物料。没有批准记录时，页面必须显示“来源产品标识，未映射 SAP 物料”。

### 3.2 供应商与工厂

需要冻结 TMS `factory_code/supplier_code` 与 SAP-B1 `CardCode` 或 MES 工厂标识的关系。别名、集团公司与实际生产地点必须分层维护，不能仅凭中文简称合并。

### 3.3 Lot 与生产单据

必须确定以下键是否由源系统保证唯一，以及其组合范围：

- Wafer Lot / Wafer ID；
- Assembly Lot / Test Lot；
- SAP 生产订单、采购订单、委外单及行号；
- MES Route、Operation、Equipment、Program Version；
- 重工、拆分、合并、返测前后的父子 Lot。

TMS 不得仅用相似字符串猜测 Lot 关系。无法唯一匹配时进入待治理队列，失败关闭。

## 4. 建议接口合同

| 编号 | 方向 | 主题 | 最小业务键 | 最小载荷 | 频率/时序 | 必须的失败处理 |
|---|---|---|---|---|---|---|
| SAP-01 | SAP→TMS | 物料主数据增量 | `ItemCode + version/effective_at` | 名称、物料组、状态、有效期、更新时间 | 增量事件或定时拉取 | 版本倒退、重复键和删除必须隔离并告警 |
| SAP-02 | SAP→TMS | 供应商/业务伙伴 | `CardCode` | 名称、状态、组织、更新时间 | 日增量 | 不自动合并同名主体 |
| SAP-03 | SAP/MES→TMS | 订单与 Lot 绑定 | 单据号+行号+Lot | 产品、数量、单位、业务状态、事件版本 | 事件或小时级 | 数量/单位不一致不得静默覆盖 |
| MES-01 | MES→TMS | Lot genealogy | `event_id` | 父子 Lot、工序、时间、数量、原因、版本 | 近实时或批量 | 乱序按版本处理；缺父节点进入待补录 |
| MES-02 | MES→TMS | 工艺/设备/程序上下文 | Lot+Operation+Event version | Route、站点、设备、程序、Recipe、开始结束 | 工序完成后 | 同版本冲突必须拒绝 |
| TMS-01 | TMS→MES/QMS | CP/FT 结果摘要 | Dataset ID+Version | Lot、产品、单位数、PASS/FAIL/UNKNOWN、良率口径、Source/Job/Release | Dataset 发布事件 | 只发送 PUBLISHED Current；重放必须幂等 |
| TMS-02 | TMS→QMS | 异常线索 | `alert_id + rule_version` | Lot、参数、证据链接、样本数、严重度、规则版本 | 规则触发后 | 明确标记“分析线索”，不能自动放行/报废 |
| QMS-01 | QMS→TMS | 规格/偏差/CAPA 引用 | QMS record ID+version | 状态、审批人、有效期、适用产品/Lot、文档引用 | 批准状态变化 | 未批准或过期记录不得作为正式 Spec |

## 5. 每个接口必须具备的技术字段

所有事件或增量记录至少包含：

- `event_id`：全局稳定幂等键；
- `source_system`、`source_instance`、`schema_version`；
- `business_key` 与其组成字段，不能只提供展示名称；
- `event_version` 或可靠的单调更新时间；
- `occurred_at_utc`、`emitted_at_utc`，并注明源时区；
- `operation`：CREATE / UPDATE / RETIRE，物理删除默认不接受；
- `correlation_id`、`trace_id`；
- 原始载荷 SHA-256 或签名、记录数及分页游标；
- 单位、精度、舍入、币种及空值语义；
- 数据 Owner、保留期和敏感级别。

## 6. 安全与运行要求

- 服务账号最小权限，读写方向分离；密码、Token、证书不得进入源码、日志或命令行参数。
- 传输必须使用公司批准的 TLS、网络白名单和证书轮换机制。
- TMS 接口先落不可变接收记录和 SHA，再做业务映射；失败重试不生成重复事实。
- 每批记录接收数、成功数、隔离数、重复数和最新水位，并可从业务对象下钻到接口事件。
- 下游不可用时进入有界重试/死信，不阻塞 TMS 已完成的正式 Dataset 发布；恢复后按幂等键重放。
- 接口不得拥有删除 FTP/NAS 原始源、SAP 单据或 QMS 审批记录的权限。

## 7. 对账与验收样例

每个接口投产前至少提供三组经 Owner 签字的 Golden 数据：正常、边界、冲突。验收必须覆盖：

1. 记录数、业务键、单位、精度、时区和空值逐字段对账；
2. 重复投递、乱序、断点续传、分页重放和部分失败；
3. 主数据停用、Lot 拆分/合并、返测/重工、跨月及跨组织；
4. 越权、过期凭据、签名错误和网络中断；
5. SAP/MES/QMS 与 TMS 双方水位和差异报告；
6. 回滚后不丢事件、不重复生成 Dataset、不改变既有 Canonical 事实。

## 8. 开放决策与签字

| 决策 | 建议 Owner | 未决时的 TMS 行为 |
|---|---|---|
| SAP-B1 使用 Service Layer、DI API、中间库或企业集成平台 | SAP-B1 运维、架构、信息安全 | 不开发生产连接器 |
| 产品、供应商、Lot、工艺版本的企业唯一键 | 主数据、生产、质量、财务 | 保持来源观察值，不自动映射 |
| MES/QMS 的事件版本与补偿机制 | MES/QMS Owner | 不接收不可幂等的覆盖式接口 |
| CP/FT 摘要进入 MES/QMS 后的业务动作 | 生产、质量 | 仅提供事实与证据，不触发自动放行 |
| 接口 SLO、告警责任、维护窗口和数据保留期 | CIO、IT 运维、系统 Owner | 只允许测试环境联调 |

生产接入的关闭条件是：字段合同、Golden 样例、安全评审、对账脚本、失败重放、回滚演练和业务签字全部完成。当前仓库只能把本清单作为后续接口的实施门，不能据此宣称 SAP-B1、MES 或 QMS 已集成。
