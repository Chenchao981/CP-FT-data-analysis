# NCE PYMS 功能规划与现状对齐 v1.0

> 2026-09-05 增量启动：用户已要求开始 FTP 服务器对接设计与实现，范围见 [FTP 对接设计](../architecture/NCE_PYMS_FTP_Integration_Design_2026-09-05.md)。替代下述 FTP 暂缓决定；SAP-B1 等其余延期事项不变。
>
> 2026-09-04 历史执行范围调整：FTP/NAS 定时自动采集和 SAP-B1 关联暂缓，不作为第一阶段可用性验收的阻塞项。第一阶段优先完成 TMS 已有 CP/FT 能力，以及个人工具的清洗、散点图、PAT、SBL/SYL 和结果历史闭环。

- 日期：2026-09-03
- 产品定位：新洁能产品与良率管理平台（NCE Product & Yield Management System）
- 当前技术工程名：TMS（暂不修改数据库、API、目录和部署标识）

## 1. 规划结论

系统应由“CP/FT 数据分析工具”升级为“正式制造数据平台 + 个人分析工具”双工作区，而不是把所有能力继续堆在 CP、FT 和快速分析三个菜单中。

两条工作区不是两套处理系统。它们共享已发布的 CP/FT Cleaner、统计公式、规则匹配、图表组件和结果合同，只在数据接入方式与结果生命周期上分开：

1. **正式制造数据平台**：形成长期、可比较、可追溯的公司数据资产，驱动产品良率、质量、异常和管理驾驶舱。
2. **个人分析工具**：承载从既有 CP、FT、VDMOS 工具迁入的定制功能，直接处理用户选择的目录、文件和压缩包，结果默认仅本人使用并按临时制品管理。

个人分析不是正式分析的简化算法，也不是另一套统计口径。两边都遵循“选择数据源 → 清洗为标准数据 → 统计分析 → 按需绘图/导出”的同一处理逻辑。正式制造区主要接 FTP/NAS 自动采集和正式上传，个人分析区主要接用户电脑目录、映射盘和手动上传；两边不能混用 Dataset 身份、保存周期、共享范围或管理指标。

## 2. 当前产品需要调整的地方

### 2.1 产品名称分两层处理

- 用户可见品牌逐步使用“新洁能产品与良率管理平台 / NCE PYMS”。
- 当前 `TMS` 继续作为内部技术代号，暂不批量修改数据库 Schema、API 路径、环境变量、部署脚本和历史文档。
- 等首页、导航、正式数据与个人工具边界稳定后，再执行单独的品牌迁移，不把品牌改名和业务重构绑在一次发布中。

### 2.2 导航按用户任务重组

建议目标导航：

| 一级入口 | 主要内容 | 数据范围 |
|---|---|---|
| 个人驾驶舱 | 我的正式数据、待办、近期异常和常用入口 | 正式数据 |
| 产品与批次 | 产品、Lot、Wafer、CP/FT阶段、SAP订单辅助信息 | 正式数据 |
| CP数据 | CP上传、自动清洗结果、产品/Lot筛选和五组分析 | 正式数据 |
| FT数据 | FT上传、自动清洗结果、产品/Lot筛选和五组分析 | 正式数据 |
| 良率与质量 | Yield、Bin、参数能力、PAT/SPC/SBL/SYL和质量趋势 | 正式数据 |
| 异常与任务 | 自动异常、人工确认、责任人、处理记录和关闭结论 | 正式数据 |
| 个人分析工具 | CP工具、FT工具、VDMOS工具、直接路径和临时结果 | 个人临时数据 |
| 数据与配置 | 数据源、产品映射、规则、运行一致性、用户与数据域 | 管理数据 |

不再增加“工程/量产”或“工厂”一级菜单。工程/量产由 SAP 订单辅助识别，晶圆厂和封测厂作为筛选维度。

### 2.3 CP/FT正式分析与个人工具彻底分层

| 对比项 | 正式CP/FT | 个人分析工具 |
|---|---|---|
| 目的 | 公司数据资产、长期比较和管理指标 | 一次性、探索性、定制化处理 |
| 输入 | 个人正式上传、FTP/NAS定时采集、后续接口 | 本地目录、映射盘、UNC、FTP/NAS临时路径、文件或压缩包 |
| 处理 | 共用已发布 Cleaner、统计规则和图表引擎；执行正式质量门禁 | 共用已发布 Cleaner、统计规则和图表引擎；保留CP/FT/VDMOS工具化操作界面 |
| 存储 | Canonical Dataset与版本 | 用户临时Workspace和结果制品 |
| 权限 | Owner、数据域、管理员 | 默认本人；开发期管理员可查看全部 |
| 生命周期 | 长期、Current/历史版本、可追溯 | 有期限、可重新执行、可下载 |
| 驾驶舱/预警 | 可以进入 | 默认不得进入 |
| 转正式 | 正式链路直接产生 | 只能创建正式重跑任务，不能复制临时结论冒充正式数据 |

### 2.4 个人分析工具采用插件式产品结构

个人分析工具页面保留用户熟悉的桌面GUI逻辑：

1. 选择工具类别：CP工具、FT工具、VDMOS工具。
2. 选择厂家/格式。
3. 选择输入路径、输出路径、文件或压缩包。
4. 预览将要处理的目录和文件清单。
5. 选择功能：清洗、图表、PAT、SBL/SYL或具体定制能力。
6. 显式点击执行，查看日志、进度、图表和下载结果。

每个工具注册：`tool_code + release_version + package_sha + input_contract + output_contract + supported_actions`。正式制造区和个人分析区引用同一个获批发布包与分析结果适配层，分别由正式Runner和Personal Tool Runner提供不同的数据入口、任务身份及保存策略。

VDMOS历史功能不得把浏览器内硬编码规格、Bin和统计公式直接写入正式分析。需要保留的定制能力以版本化工具包运行，并在结果中标明工具和版本。

## 3. 目标功能架构

### 3.1 正式制造数据平台

#### 数据资产

- 个人正式上传；
- FTP/NAS定时采集、去重和断点续跑；
- CP、FT标准化数据与来源追溯；
- 产品、Lot、Wafer、Unit、参数、Bin、规格和测试条件；
- SAP-B1产品、生产/工程订单辅助映射。

#### 分析中心

- 五个中文分组：分析总览、参数图表、晶圆空间、质量管控、报告与数据；
- CP显示晶圆空间，FT隐藏坐标类能力；
- 产品、多Lot、多Dataset和厂家维度比较；
- 服务端自动匹配当前有效规则；
- 保存分析、图表组合模板和异步报告导出。

#### 良率与质量闭环

- 产品良率驾驶舱；
- Yield、Bin、低良Lot、异常Wafer和异常参数；
- 自动基线和异常检测；
- 异常任务、负责人、证据、结论和关闭；
- 供应商/晶圆厂/封测厂表现，但不单独拆工厂菜单。

### 3.2 个人分析工具

- CP定制工具：按晶圆厂和现有CP程序组织；
- FT定制工具：按封测厂和现有FT程序组织；
- VDMOS定制工具：保留适合个人探索的一次性图表与分析；
- 直接路径预览、压缩包解析、输入/输出目录、功能按钮和执行日志；
- 临时结果只进入个人记录，不参与正式良率、管理驾驶舱和自动预警；
- 支持“使用同一源数据创建正式入库任务”，由正式Cleaner重新处理。

### 3.3 共用处理核心

- CP 与 FT 仍按测试阶段、厂家格式调用各自成熟的 Cleaner，不做自动猜测或重新编写厂家解析器；
- 无论来自 FTP/NAS、个人电脑目录还是手动上传，清洗成功后都进入相同的标准数据合同，再调用同一套统计、PAT/SBL/SYL、规则和图表能力；
- 图形按用户选择后再绘制，避免加载数据集时一次性生成全部图形；
- 正式结果写入 Canonical Dataset 并参与公司指标，个人结果写入个人 Workspace，默认不参与正式 KPI 和异常预警；
- 同一算法版本对相同标准输入应输出一致统计结果，两种入口的差异只体现在来源、Owner、追溯、保存和发布范围。

### 3.4 后续扩展

- WAT、封装过程、WIP、可靠性、客诉/RMA；
- CP到FT的Lot/产品/制造批次关联；
- 产品全生命周期追溯；
- Yield、质量、交付和成本影响；
- AI产品工程助手和根因候选排序。

## 4. 分阶段开发顺序

### P0：产品边界与可用性收口（现在）

1. 用户可见产品名逐步调整为 NCE PYMS，内部技术标识保持 TMS。
2. 将“快速分析”重命名为“个人分析工具”，页面内明确 CP、FT、VDMOS 三类。
3. CP/FT页面只展示正式上传和自动采集形成的正式数据，不混入个人临时任务。
4. 完成服务端规则自动匹配，普通用户不再处理规则编号和版本。
5. 将统一结果组件从 PAT 扩展到描述统计、箱线图、分布、散点、趋势和质量结果。
6. 统一产品、Lot、厂家、来源和订单分类术语。

**验收结果**：用户不用理解 Dataset ID、Rule Code 或工具内部版本，就能完成正式分析；个人工具仍保持原GUI式使用方法。

### P1：YMS核心闭环

1. FTP/NAS数据源中心、定时任务、文件指纹去重、失败重试和任务监控。
2. 产品与批次页面：产品 → Lot → Wafer/Unit → 参数/来源钻取。
3. 产品良率驾驶舱：CP Yield、FT Yield、异常Lot、低良Wafer、异常参数。
4. 跨批次和跨厂家比较，显示数据兼容性和不可比较原因。
5. 用户图表组合、模板保存、一键生成HTML/PDF/XLSX报告。
6. 异常中心：自动发现、人工确认、分派、处理和关闭。

**验收结果**：系统能够回答“哪些产品、批次、晶圆或供应商正在异常”，而不仅是展示图表。

### P2：PYMS产品链路

1. 接入SAP-B1产品、BOM/物料和工程/量产订单辅助信息。
2. 建立CP → 封装 → FT的批次谱系与数量对账。
3. 接入WAT、封装过程、WIP和可靠性数据。
4. 产品、供应商、工厂、程序和测试机的多维良率与质量评价。
5. 产品生命周期质量档案与客诉/RMA关联。

**验收结果**：系统能够从产品下钻到制造阶段，并解释CP、封装、FT和质量事件之间的证据关系。

### P3：制造智能

1. 动态基线、趋势变点、空间Pattern和多参数异常检测。
2. Good Lot/Bad Lot对比与Root Cause Candidate Ranking。
3. AI产品工程助手：自然语言查询、自动取数、证据链接和报告草稿。
4. Yield变化对应Good Die、测试成本、报废和潜在经营影响。

**验收结果**：系统主动提出异常和调查候选；AI结论可追溯到正式数据与规则，不替代工程师签字。

## 5. 近期开发任务优先级

| 优先级 | 功能包 | 原因 |
|---|---|---|
| P0-1 | 正式数据与个人工具导航分层 | 先消除产品定位混乱，避免后续继续耦合 |
| P0-2 | 个人工具注册与CP/FT/VDMOS分类 | 保护现有工具价值，并通过共用处理核心持续升级和添加厂家 |
| P0-3 | 正式规则自动匹配 | 直接减少普通用户技术输入 |
| P0-4 | 通用分析结果合同 | 避免正式分析和个人工具各做一套图表表现 |
| P1-1 | FTP/NAS自动采集闭环 | 把人工文件转换为持续数据资产 |
| P1-2 | 产品与批次驾驶舱 | 从“看图”升级到产品良率管理 |
| P1-3 | 异常与任务闭环 | 从被动查询升级到主动管理 |
| P1-4 | 组合模板与综合报告 | 固化工程师重复分析流程 |

## 6. 当前不应优先做的事项

- 不批量重命名数据库、API、环境变量和部署脚本；
- 不把快速分析结果自动写入正式Canonical数据；
- 不把工程/量产、晶圆厂/封测厂拆成更多一级菜单；
- 不继续以增加图表数量作为主要完成度；
- 不在CP、FT、WAT和SAP身份链路稳定前开发AI根因概率；
- 不让VDMOS历史HTML成为第二套正式统计引擎。

## 7. 关键产品指标

近期不以“图表数量”衡量成果，改用：

- FTP新文件自动形成正式数据的成功率和时延；
- 产品/Lot/Wafer/Unit身份可追溯率；
- 正式Dataset具有有效Yield、Bin、Spec和参数身份的覆盖率；
- 异常从发现到确认、分派和关闭的时间；
- 重复人工分析步骤减少量；
- 个人工具任务耗时、成功率和复用次数；
- 管理驾驶舱指标可下钻到正式数据证据的比例。
