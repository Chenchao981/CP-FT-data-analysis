# TMS 与新洁能业务适配评估

- 评估日期：2026-08-30
- 公司：无锡新洁能股份有限公司（NCE Power）
- 信息边界：仅采用公司官网及官网披露文件中的公开事实；公开材料不能替代内部工艺、Spec、Bin、SAP-B1 物料和质量口径批准

## 1. 官网公开事实

- 产品已覆盖 IGBT、SGT/SJ/Trench MOSFET、车规功率器件、SiC MOSFET、GaN HEMT、功率模块、栅极驱动 IC、电源管理 IC、IPM 和 MCU 等平台，细分型号接近 4,000 款，电压覆盖 12V～1700V；
- 芯片产品采用设计后委托晶圆代工的模式；功率器件由子公司及外部封装测试企业共同完成封装测试，电基集成已形成部分自主封测能力，金兰半导体已建设功率模块生产线；

## 2. 对 TMS 的直接含义

### 2.1 当前方向正确的地方

1. **CP 与 FT 分开**：晶圆代工、内部封测和外部封测并存，决定了 CP/FT 不能依赖一个自动猜测入口。当前“工程/量产 × CP/FT”四个固定入口符合实际业务分工。
2. **厂家差异留在 Cleaner**：供应链包含不同晶圆厂和封测厂，原始格式、单位、Bin 和程序语义必然不同。TMS 复用已发布 Cleaner、通过 Adapter 写入统一 Canonical，比在平台中重写各厂解析器更稳妥。
3. **血缘是核心资产**：Source、厂家、Lot、Wafer/Unit、测试程序、Cleaner Release、Spec Set、Job、Dataset Version 的追溯，能够支撑多供应商质量分析和异常复盘。
4. **UNKNOWN 独立呈现**：没有 PASS/FAIL 证据时不伪造良率，符合质量系统对证据和一致性的要求。
5. **正式分析与 Quick PAT 分离**：一次性大数据统计不应被迫写入数百万条正式 Measurement；需要长期质量追溯的数据则进入 Canonical。

### 2.2 本轮必须改进的地方

1. **从技术编号转为业务检索**：近 4,000 个型号和多供应商场景下，一线人员应按 Product、Lot、Wafer、厂家、Cleaner 和时间查找，不应手填 Dataset/Job/Run ID。
2. **Product 身份必须可补录且可追溯**：Cleaner 原值、人工业务有效值和未来 SAP-B1 物料 Crosswalk 要分层保存，不能用一次覆盖丢掉原始证据。
3. **多数据集比较必须服务端重算**：跨 Lot/Wafer/Bin/参数比较要使用当前筛选后的数据库事实，并在单位、测试条件或 Spec 不一致时失败关闭。
4. **领导首屏突出决策指标**：优先显示已知良率、UNKNOWN、异常任务和数据新鲜度，再按产品、厂家、阶段下钻；技术方法和血缘信息按需展开。
5. **时间口径统一为上海业务时间**：页面输入采用 Asia/Shanghai，API 使用 UTC 左闭右开边界，趋势按上海业务日分组，避免跨日误判。
6. **多 Lot Spec 不能靠文件名猜测**：只有每个 Lot 都有可核验 Spec 证据且规范化合同一致时才能共享；否则继续阻断。

## 3. 领导视角的后续建设重点

这些方向重要，但不应在本轮功能收口中伪装完成：

- 将 Product/Project 与 SAP-B1 物料、产品系列、应用领域建立经过业务 Owner 审批的 Crosswalk；
- 建立晶圆厂、封测厂、内部电基产线的可比质量口径，同时保留厂家原始 Bin/参数语义；
- 把 CP→封装→FT→成品批次的跨阶段 Genealogy 作为独立项目设计，不能仅凭同名 Lot 自动关联；
- 在质量部门批准方法和阈值后，再建设 PAT/Cpk/SPC、车规批次和可靠性试验视图；
- 成本、毛利和经营分析应与 SAP-B1 成本事实对接，不能从测试良率直接推断财务毛利；
- 官网披露的 IATF16949/AEC-Q101 是公司及产品体系事实，不代表任一 TMS Dataset 自动满足认证要求。

## 4. 结论

TMS 当前最有价值的基础不是“图表数量”，而是把多晶圆厂、多封测厂、多产品平台的数据变成严格可追溯的 CP/FT 事实。本轮采用的最小正确路线是：保留四入口和 Cleaner 复用，关闭提交、恢复、历史检索、多选分析、分页明细、Quick Manifest 和管理下钻断点；不在没有内部批准数据时扩建 SAP、质量认证或通用 BI 语义。
