# TMS 开发期权限与用户入口需求（2026-09-02）

## 1. 当前目标

开发阶段以“好用、功能完整、调试方便”为第一优先级。安全收敛不作为当前功能上线门槛，待核心 CP、FT 和个人工具调用稳定后统一处理。

## 2. 用户与数据权限

1. 普通 CP/FT 用户上传的数据默认归属本人，可查看、分析、导出和处理自己的数据。
2. 普通用户获得数据域授权后，可查看和分析该域数据。
3. `SYSTEM_ADMIN` 和 `DATA_DOMAIN_ADMIN` 在开发期默认拥有全部 PERSONAL、DOMAIN 数据的查看、分析、导出和操作能力，便于定位问题。
4. `business_domain` 和 `factory_code` 是数据标签，不是权限条件。
5. 当前不增加 break-glass、审批流、临时授权等复杂安全流程。

## 3. CP/FT 统一入口

1. 用户菜单只保留“CP 数据”和“FT 数据”，不再拆分工程 CP、工程 FT、量产 CP、量产 FT。
2. 工厂不作为菜单层级；上传时只选择对应的解析工具，以复用现有 CP/FT Cleaner 和 PAT 能力。
3. 工程和量产数据可位于同一 FTP 目录，TMS 不要求按业务类型拆文件夹。
4. 历史记录按 CP/FT 合并查询，旧工程/量产链接自动跳转到新入口。

## 4. 工程/量产判定

目标口径是：从源文件得到批次号，再关联 SAP 量产单和工厂订单信息，判定工程或量产。

当前 SAP 关联尚未实现。为兼容既有数据库必填字段，统一入口新上传暂以 `ENGINEERING` 作为技术占位；该值不是最终业务结论，也不应参与权限判断或管理决策。后续必须以 SAP 判定结果回填，并保留判定来源和时间。

## 5. 快速分析

快速分析面向个人 CP/FT 工具使用。大目录文件由 Local Agent 在用户电脑附近调用既有工具计算，只上传统计结果和必要证据，不要求先上传全部源文件。

## 6. 后续开发任务

1. 建立批次号到 SAP 量产单、工厂订单的查询接口与缓存。
2. 定义 `工程 / 量产 / 未判定 / 冲突` 四种判定状态及人工纠正入口。
3. 取消新数据对 `ENGINEERING` 技术占位的依赖，并迁移已有占位记录。
4. 将同一 FTP 根目录注册为 CP/FT Source Catalog，解析工具与目录解耦。
5. 核心功能稳定后，再按安全延期清单集中收敛权限。
