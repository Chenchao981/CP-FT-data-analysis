# TMS 快速分析业务需求 v0.1

- 状态：已确认，进入开发
- 日期：2026-08-26
- 适用范围：CP/FT 数据分析系统的快速计算通道
- 关联基线：`TMS_Business_Requirements_v0.2.md` 中的正式清洗、正式入库和历史分析规则继续有效
- 2026-09-01 补充：Local Agent 已形成开发候选；数据归属与安全边界以 `TMS_Data_Ownership_and_Local_Analysis_Requirements_v1.0_2026-09-01.md` 为准

## 1. 决策

TMS 采用“双通道、同一套工具内核”的业务模式：

| 通道 | 适用场景 | 明细数据落点 | 结果用途 |
|---|---|---|---|
| 快速计算 | 一次性 PAT、良率、统计和图表 | 不进入 Canonical；仅保留来源清单、参数、状态和结果文件 | 快速决策、下载、复核 |
| 临时 Workspace | 需要多轮筛选和交互分析 | Parquet/Arrow 临时数据，带 TTL | 后续阶段建设 |
| 正式入库 | 追溯、跨批次比较、长期报表、审计 | `test.test_run -> test.unit_result -> test.measurement` | 正式事实和长期分析 |

快速计算不是正式入库的快捷入口。快速计算结果不得自动或静默转成正式数据；如需正式化，必须重新执行正式导入并通过正式数据合同。

## 2. 当前痛点

对已经位于 FTP、NAS 或服务器挂载目录中的大量源文件，先逐文件上传、再清洗入库、再选择数据计算，会产生重复传输和不必要的全量明细写入。例如 520 个 FT CSV 的一次性 PAT 只需要参数统计结果，不需要先生成数百万行正式测量事实。

浏览器受安全模型限制，不能让后台任意浏览用户个人电脑。服务器目录只允许访问管理员预先配置并绑定 `data_domain_code` 的受控 Root；用户电脑目录由 2026-09-01 新增的回环 Local Agent 通过原生目录选择器取得，网页和服务器仍不能接收本机绝对路径。该 Agent 当前是开发候选，不是已完成的生产受信设备方案。

## 3. P0 范围

首个可运行切片固定为：

- 测试阶段：FT；
- 封测厂：杰群（`JIEQUN`）；
- 分析类型：原始目录低内存 PAT（`QUICK_PAT`）；
- 输入合同：一个受控根目录下的相对目录，且为已验收的杰群统一 CSV 格式；
- 计算内核：调用已发布 `ft_data_cleaner.pyz` 中的成熟 PAT 实现，不在 TMS 重写解析、单位换算、参数筛选、四分位数或控制限公式；
- 持久化：保存任务、来源 Manifest、工具 Release、统计摘要和 PAT Excel；不保存逐颗器件测量明细；
- 默认结果保留期：7 天，可由部署配置调整；
- 权限：具有 `ANALYSIS_RUN` 的用户可创建和查看自己的 `PERSONAL` 快速分析；系统管理员没有隐式结果读取权，跨用户审计需要独立、受控且可审计的权限流程。

## 4. 用户流程

1. 用户进入“快速分析”。
2. 系统只展示管理员配置且当前可用的服务器数据源。
3. 用户在数据源内逐级浏览目录并选择目标目录；界面不暴露服务器真实根路径。
4. 系统提交 QUICK_PAT 会话并立即返回会话号和后台任务号，不上传源文件。
5. Worker 在数据附近重新解析受控路径，校验来源 Manifest 未变化，并调用已发布 PAT 工具。
6. 用户查看排队、运行、成功或失败状态；成功后下载 PAT Excel。

## 5. 数据与审计合同

每次快速分析至少记录：

- 用户身份、创建时间、分析类型、测试阶段和厂家；
- `source_root_code + source_relative_path`，不得接受任意服务器绝对路径；
- 来源文件相对路径、大小、最后修改时间以及 Manifest SHA-256；
- Cleaner/PAT Release ID、代码 SHA-256 和后台任务 ID；
- 文件数、总字节数、参数数、运行状态、错误信息和结果摘要；
- PAT Excel、摘要 JSON、来源 Manifest JSON 的 URI、大小和 SHA-256；
- 结果过期时间。

Manifest P0 使用 `PATH_SIZE_MTIME_V1`，避免为了提交任务再次顺序读取数 GB 文件。该模式能发现常见的增删改，但不是逐文件内容哈希；需要长期审计时必须走正式入库或升级 Manifest 合同。

## 6. 安全与失败关闭

- 数据源根路径只能由部署配置提供，不能由普通用户创建或修改。
- API 只接收数据源代码和相对路径；绝对路径、盘符、UNC、`..`、符号链接或重解析点逃逸必须拒绝。
- Worker 执行前必须重算 Manifest；来源在排队期间发生变化时任务失败，不使用不一致数据继续计算。
- 工具包不存在、SHA-256 与已发布 Release 不一致、格式不是已批准统一 CSV、混入多个产品、参数布局不一致或结果合同不完整时均失败关闭。
- 原始文件只读；所有临时文件和结果写入独立工作目录。

当前“已发布工具”表示 Cleaner Registry 记录与单文件 SHA-256 固定，不表示工具包已经
完成代码签名。Local Agent 返回的 Manifest 与结果回执是自声明一致性材料，不是设备
签名或可信执行证明；生产签名、服务端 nonce、防重放和设备身份仍是开放门。

## 7. P0 验收标准

- 无需上传 520 个原始文件即可创建 QUICK_PAT 任务。
- 真实 520 文件目录能够通过新 API、SQL 队列和 Worker 完成一次端到端计算。
- PAT 结果与已发布桌面工具结果逐单元格一致。
- 记录实际耗时、峰值内存或可观测替代证据、临时磁盘和输出大小。
- 普通用户不能越权查看其他用户会话，也不能通过相对路径访问受控根目录之外的数据。
- 快速分析运行后 `test.*` 正式事实表行数不增加。
